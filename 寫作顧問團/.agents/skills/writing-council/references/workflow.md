# 流程與狀態規則

## 狀態順序

```text
選題討論 → 企劃 → 研究 → 寫作 → 審稿 → 修改 → 排版 → 完成
                                  ↑       ↓
                                  └───────┘
```

任何階段都可以由使用者明確要求退回。退回後，不刪除既有成果；將受影響的下游檔案標記為「可能過期」。

## 交接規則

交接前必須同時滿足：

1. 當前階段的必要文件已存在。
2. 文件中的必要欄位已完成，或清楚標記待補事項。
3. 使用者明確表示確認。
4. `00-目前進度.md` 已記錄下一階段與下一角色。

交接訊息應包含：

- 已確認的決策
- 尚未解決的問題
- 鎖定內容
- 交付檔案
- 下一位 Agent 的任務

## 階段契約

### 選題 Agent

釐清讀者、平台、目的、核心問題與差異化角度。提供少量可比較選項並討論取捨。不得直接寫完整文章。

### 企劃 Agent

把已確認選題轉成文章策略、大綱、篇幅、語氣、開場方式、證據需求與行動呼籲。不得推翻選題。

### 研究 Agent

依企劃的證據需求整理來源、事實、案例、可用引述與不確定性。來源不足時明確標示，禁止補造資料。

### 寫作 Agent

只依已確認的選題、企劃與研究包寫作。保留段落 ID。遇到資料缺口時標記並要求退回研究，不自行發明。

### 審稿 Agent

先提出問題與編號建議，不擅自改稿。分開處理結構、論證、事實、語氣、冗贅及平台適配問題。

### 排版 Agent

只處理標題層級、段落、符號、重點、平台限制與發布格式。除非取得同意，不改變核心論點。

## 新對話接續

1. 先讀 `00-目前進度.md`。
2. 再讀其中列出的最新版本與待處理檔案。
3. 用一句話確認目前階段、角色及下一個待決事項。
4. 不要求使用者重新敘述已寫入檔案的背景。
